  **P1 — Token budget / S2 / Stage 2 A1+A2: the two applied fixes contradict each other.** A1 forbids `session_drift.py` from reading tool-result payloads. A2's throttle requires "at least 25,000 characters of context elapsed since the last check." The `PostToolBatch` payload carries the batch's tool calls and outputs; it contains no cumulative context metric. The only remaining source is the transcript, which the spec warns "is written asynchronously and may lag the in-memory conversation." There is no data source for the character floor that does not violate A1. Both cannot be implemented; one has to give, and nobody noticed because A1 and A2 were reviewed as separate findings.

  **P1 — S3: PreCompact cannot emit context.** The spec gives PreCompact exactly one output channel: `decision: "block"`. `additionalContext` is delivered only on SessionStart, UserPromptSubmit, Pre/PostToolUse, PostToolBatch, and Stop/SubagentStop. "PreCompact writes the current scratch file and emits it" is infeasible as written, and the budget line "PreCompact re-injection: <= 1,500 characters" prices a channel that doesn't exist. The real re-injection point is SessionStart with `source: "compact"` — which the plan's own Finding 4.1 already wired into the S1 router. So the slice the plan calls "the single highest-value moment for the whole plan" is mechanism-wrong, and the correct path makes the PreCompact hook nearly redundant (a file flush the drift check and router already do). Both reviews checked the budget, the staleness, the schema — neither checked whether the event can carry the payload.

  **P1 — Stage 2 A9: the self-diagnosis is circular.** `session_router.py` is itself delivered by the SessionStart hook. The failure A9 names — modules installed, hooks unwired, operator believes the system is live — is exactly the state in which the router never executes and can log nothing. A9 detects partial wiring only (router present, three others absent); the total-wiring miss it was written to catch remains silent. The check belongs in the installer or a status command — something that runs whether or not hooks are wired — not inside a hook.

  **P2 — S3 / Validation commands: slice text was never reconciled with Stage 1's own resolutions.** Finding 5.1 collapsed `session_precompact.py` + `session_end.py` into `session_lifecycle.py`; 5.2 added `session_state.py`. S3 still lists `session_precompact.py`, `session_end.py`, `state_reaper.py` as its files, and the validation command still runs `test_session_end.py` with no `test_session_lifecycle.py` or `test_session_state.py`. An implementer following the slices builds modules the review record says no longer exist. The review amended the prose around the plan, not the plan.

  **P2 — S2: the drift check's information source is an unstated assumption.** A1 says drift context comes from "operator-authored turn text only," but `PostToolBatch` delivers tool calls, not prompt text — so the source must be the transcript JSONL, which lags the live turn by an unspecified amount. "What has happened since the last check" is built on a stale, asynchronously-written file whose currency nobody bounded. On a fast session the most drift-relevant turns are precisely the ones missing.

  **P2 — Executive decision / slices S0–S7: this is three plans wearing one coat, and the weakest third carries the highest risk.** The two headline questions need only: scratch file + SessionStart router (startup/resume/compact) + SessionEnd verdict + reaper + `/curator`. S2 (drift check), S5 (`/sweep`), S6 (personas) are unrelated feature bundles glued on because the grill happened to surface them the same day. The drift check is the worst offender: its value is a question the operator can type, its failure mode (attention noise) is the one the pre-mortem calls most likely, and it adds an always-on event surface to an ecosystem whose motivating incident was one hook injecting 13.5 KB unrequested. Seven modules and four hooks is more machinery than "survive compaction, verify at close" deserves. Ship the core; split the rest.

  **P2 — Why now / Approval gate: the hotfix smoke number indicts the retained behavior.** The post-fix test reports the operator's own two-word "co dalej?" still emits **12,490 bytes**. The hotfix closed the provenance hole, not the oversensitivity — trivial operator text still triggers an injection the same order of magnitude as the 13.5 KB incident the plan exists to react to. Both reviews accepted "pasted text fires 0 bytes" as proof of success and neither asked why 12.5 KB on "what's next?" is acceptable. The DoD tests provenance only; nothing bounds trigger rate on ordinary operator prompts.

  **P2 — S3: the SessionEnd verdict has no delivery channel.** SessionEnd has no decision control and its stdout goes to the debug log, not the transcript. "It reports; it never archives" never says *where* — `systemMessage`, a file, the handoff draft? If the answer is the debug log, headline goal #2 ("a verified verdict instead of a self-report") is invisible at the only moment it matters.

  **P3 — S3: the reaper has no guaranteed trigger.** It runs from SessionEnd, but a killed or crashed session never fires SessionEnd — and on Windows kill is the common exit. "Separately invocable" means unscheduled. The DoD item "backlog cannot grow unbounded again" holds only if every session exits cleanly; the 1,944-file backlog it cleans up exists precisely because they don't.

  **P3 — S0: file list is stale post-`ad12cf2`, and the copy direction is undefined.** `answer_footer.py` is already tracked in the repo (the hotfix touched it); `repo_hygiene_nudge.py`, `memory_size_guard.py`, `autoplan_review_workflow.js` are not. S0 still lists all four as untracked copies-to-make. And where installed and canonical copies have diverged since, "copy + verify byte identity" silently blesses whichever side you copy from — no merge or freshness rule is stated.

  **P3 — S5: the gate contradicts the slice.** "Read-only, proven by before/after `git status`" versus a slice whose function is appending to a tracked `IDEA_BOX.md`. As written the gate can only pass on a repo with zero findings — which is the only case the test matrix lists. Restate as "no writes outside `IDEA_BOX.md`."

  **P3 — Token budget: the verdict table has dead rows.** Rows 3 and 4 yield `CHECKPOINT` on every input; the "Context used" column decides nothing anywhere. A5's resolution was right, but the honest table is two rules (`merged+clean+no open items` → ARCHIVE-OK; merged → HANDOFF; else CHECKPOINT) plus a reported statistic — not four rows parading a variable that never matters.

  **P3 — Discarded table / S6: "operator-0931 assumes one market open" was dismissed too cheaply.** "Prompt text, tuned at use" means it ships untested — yet S6's gate checks persona *selection*, not persona *quality*, and a persona anchored to a US-market open will be proposed for repos and hours where it's irrelevant. The discard answered "is this a gating defect" (no) and skipped "does the gate cover this class" (also no).
