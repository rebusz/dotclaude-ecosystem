# CoderPX G — task-selected providers

Operator decision 2026-10-10 supersedes rigid cloud-author/local-integrator roles,
mandatory five-model Perplexity participation, and mandatory workflow invocation.
Read [local-implementation.md](references/local-implementation.md) before assigning
work and [workers.md](references/workers.md) for local workers. These instructions
change routing policy, not executable adapters, guards, receipts or permissions.

Accept an idea, task or exact plan path. Read repo intent and plan context;
reuse the relevant plan and preserve existing scoped GO. R2/R3 retains a plan,
blast radius, rollback, real-path validation and independent exact-head review.
R0 follows repository documentation publication rules. `/coderpxg`, `/fwf` and
`/fwp` are optional helpers; resume an already selected workflow rather than
creating duplicate attempts or another delivery owner.

1. Assign bounded roles by difficulty, local capability, source access and fresh
   capacity evidence. ChatGPT CDP, Perplexity, Antigravity, Cursor, z.ai GLM and
   supported local workers may implement or independently audit when qualified.
   One suitable Perplexity model is allowed under the recorded review contract.
   Claude CLI Opus 5.5/Fable is optional critical-decision advice, not a routine
   worker or mandatory reviewer. Verify actual model and supported effort.
2. Give each assignment exact base, owned root/write-set, acceptance checks and
   stop conditions. Local implementation requires edit-capable access; browser
   answers may need a separately assigned local applier. Any capable local model
   may author substantive code and tests. Run disjoint assignments concurrently
   under existing resource admission and retain one integration owner.
3. Retain actual response/receipt, applicable diff and real local check exits.
   Attribute all authors and material integrator edits. Catalogs, advertisements,
   dry-runs and success prose are not execution proof. Use the provider's actual
   supported adapter and source contract; do not invent a driver or schema.
4. Assign formal review to a qualified reviewer independent of every substantive
   producer. A different transport alone is insufficient. Review the actual
   current diff/source; unavailable or stale evidence is NO_REVIEW. Fix blockers,
   validate and review the corrected head. No author self-clearance or invented
   quorum. The unchanged `fuse.py` remains an optional legacy fixed-roster route;
   manual task-selected review uses supported adapters with the same gates.
5. One delivery owner completes authorized Git/PR/CI/merge and checkout sync.
   Preserve self-hosted CI, source confidentiality, shared caps and attempt IDs.
   SUBMIT_UNCONFIRMED forbids retry/replacement or duplicate completion; reconcile
   the same attempt and continue only independent work. Deployment, destruction,
   scope expansion and real-money/Combine triggers retain separate authority.

Read provider quota where supported; missing telemetry stays UNKNOWN. Operator
accounts are not automatically rotated. `/model-team` forwards the existing task,
plan, scope and stage once; it does not reset receipts or own another closeout.
